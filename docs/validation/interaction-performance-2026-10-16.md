# Nexlet 交互性能对比（2026-10-16）

本次实现了获批的 macOS 原生唤起、搜索配置快照与分阶段结果、剪贴板摘要分页与虚拟列表，并完成前后对比。收益集中在唤起、搜索结果到达、长文本历史打开和内存；启动及滚动帧间隔没有得到稳定改善的证据。

## 实现范围

- macOS 显示窗口前复用现有原生接口读取前台应用；失败时回退 JXA，原生返回空值时保留已有有效目标。
- 搜索请求只读取一份命令配置，不执行完整状态同步、自启动查询和快捷键同步。先显示普通搜索、非正则规则及内置结果，再补正则匹配；图标独立加载。请求 ID 与有效期检查隔离旧查询响应，保持计算稿纸优先级。
- 正则 Worker 按窗口复用，正常完成后空闲 30 秒回收；取消、超时或关闭窗口时销毁。保留单条 20 ms、整批 200 ms 的执行预算及父进程 1 秒兜底。
- 剪贴板沿用现有表，先获取轻量 ID 索引，每页最多 40 条摘要；文本摘要不超过 600 个 UTF-16 单元，字符统计仍按 Unicode code point。展开按 ID 获取全文，复制仍读取原始完整记录。全文搜索、收藏、类型、中转范围与最近使用排序保持原语义。
- 只渲染可见行和缓冲行，按实际高度修正位置；新增记录时保持浏览锚点。跨页多选及独立窗口的筛选、选择、光标、展开状态得到恢复。保留旧 `clips` 接口，无数据库迁移。

## 测量方法

基线为 `f673562f55314df72bd46d04ec19e900ab47412b`；after 为该基线加本次未提交改动。两份构建冻结后执行，不直接比较运行中的开发构建。主进程、Worker、Renderer 与依赖锁文件的 SHA-256 见[原始 JSON](./interaction-performance-2026-10-16.json)。两份依赖锁文件哈希一致。

- 环境：Apple M3 Pro、macOS / Darwin 25.5.0、arm64、Electron 44.7.0 / Chromium 152.0.7977.130；基准驱动 Node 24.19.0。
- 数据：每个进程独立 userData，500 条各 32,768 字节的合成长文本；1,000 个合成命令、100 条命令偏好、8 条正则规则。没有读取或写入真实系统剪贴板。
- 每份构建先预热 1 次且丢弃，再做 5 轮交替 before/after。计量期间未并行运行构建或测试。
- 每份构建：唤起 40 次，搜索 IPC 50 次，搜索界面 25 次，启动 / 剪贴板打开 / RSS 各 5 次。搜索最终结果样本包含每次新进程的首次 Worker 启动。
- 中位数使用通常的中位数；P95 使用排序后 `ceil(0.95 × N)` 的值。5 个样本的 P95 即最大值，不能当作稳定尾延迟估计。

## 结果

耗时单位为 ms；括号内为 P95。变化按中位数计算。

| 指标 | 每份样本数 | Before | After | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 主进程唤起流程 | 40 | 67.48（109.70） | 4.04（7.74） | −94.0% |
| 搜索首批结果 IPC | 50 | 36.75（47.90） | 2.00（14.10） | −94.6% |

| 剪贴板首批数据 IPC | 5 | 51.20（78.10） | 8.50（13.90） | −83.4% |
| 进程启动到首页可见 | 5 | 821.06（864.41） | 810.27（1,259.16） | −1.3%，不认定改善 |

首批剪贴板数据的 JSON UTF-8 大小从 **16,435,281 B 降至 33,596 B（−99.80%）**。after 包含全部 500 个 ID 的索引及第一页 40 条摘要；before 是旧接口返回的完整 500 条记录。这是业务载荷大小，不包括 Electron IPC 协议开销。

首屏记录 DOM 数量从 **500 降至 11**；滚动期间峰值从 **500 降至 18**。打开至滚动结束的 Long Task 观察中，before 每轮各有 1 次 86–91 ms 的任务，after 本次未观测到超过 50 ms 的任务。观察区间同时包含打开和滚动，不能把这些任务全部归因于滚动。

## 口径与限制

- 唤起测量是 `show()` 开始到同步 reveal 流程完成，包含前台目标读取；不等同于物理按键到屏幕像素出现的延迟。
- 搜索 IPC 不包含 UI 的 60 ms debounce；“输入到首批界面结果”包含 debounce，使用 DOM input 事件到 requestAnimationFrame 中可见匹配项的时间，因此更接近输入后的界面响应。
- 剪贴板打开从点击工具到首批非空记录在 animation frame 中出现。它证明首屏可用更快，不代表已加载全部历史。
- RSS 为 Electron 所报告进程 PID 的 OS RSS 相加，共享页可能重复计算；在打开后、额外读取完整数据之前采样。不是独占物理内存，也不是长期运行峰值。
- 滚动每轮记录 120 帧，统计时排除第一帧，共 595 个间隔。当前结果约为 60 Hz；DOM 减少没有在本场景转化成可证实的帧率提升。
- 启动范围 before 为 740–864 ms，after 为 720–1,259 ms。样本重叠且 after 存在更慢样本，不宣称启动提速。没有清空 OS 缓存，计量也包括 Playwright 启动开销。
- 这些结果来自固定的长文本合成负载，不能直接推广到任意真实历史、图片占比、插件规则数量或硬件。Windows / Linux 未做实机性能对比；本次保留其平台实现，通用单测通过不替代实机验收。

## 验证

- 基线：`npm run typecheck`、433 项单元测试、`npm run build` 通过。
- 改动后：`npm run typecheck`、441 项单元测试、`npm run build` 通过；最后调整超时 Worker 回收后，相关 20 项 matcher 单测再次通过。
- 最终相关 Electron 回归：38 / 38 通过，涵盖 alignment、backspace-navigation、calculation-match、catalog-icons、clipboard-lru、entry-alignment、interaction-performance、launch-preview、lazy-tools。
- 新增覆盖：原生目标与回退、分阶段匹配及取消、Unicode 全文过滤、分页版本失效、完整复制、跨页选择、独立窗口恢复、浏览中新增记录保持位置，以及图片展开 / 收起后的相邻行布局。
- 滚动回归先复现了刷新跳回旧选中项的问题，修正后连续 3 次及最终整组通过。图片测试的初始夹具文件名不符合现有图片协议，修正夹具后通过。
- 中间运行中，搜索 E2E 有过在输入前页面意外变成插件管理而超时的情况，原因未确认；随后连续两次及最终整组通过。没有将失败样本当作性能测量样本。
- 构建仍有既有 OpenCV Node 模块 externalized 与大 chunk 提示；构建成功，没有因本次改动处理无关依赖。
