# Nexlet 实施计划

基于已批准的 `../specs/2026-10-11-nexlet-design.md`，在当前会话执行，不增加审批点。

## 1. 工程和可测试的核心逻辑

文件：`package.json`、`tsconfig*.json`、`vite.config.ts`、`scripts/build.mjs`、`src/shared/*`、`tests/core.test.ts`。
建立 Electron/React/TypeScript 本地工程及 Windows/macOS 打包配置。先编写搜索、计算和插件 manifest 边界测试，再实现对应逻辑。
验证：`npm test`、`npm run typecheck`。测试不可依赖真实用户剪贴板或外部服务。

## 2. 桌面服务和持久化

文件：`src/main/{index,store,catalog,clipboard,platform,windows,plugins}.ts`、`src/preload/*`。
实现单实例、托盘、快捷键冲突反馈、应用/快捷方式索引、SQLite、剪贴板捕获、文件格式和前台目标回贴。实现 sandbox 插件窗口、授权检查和安全导入。
验证：存储重启恢复、过期清理、非法包拒绝、插件隔离；平台适配能力返回明确状态。

## 3. 还原截图界面及内置工具

文件：`src/renderer/{App,Launcher,Clipboard,Scratchpad,Tools,Plugins,Settings}.tsx`、`styles.css`。
实现最近/固定图标网格、分组搜索、完整插件视图、计算稿纸与剪贴板，支持深色和系统主题。实现附加工具和网页快捷方式。
验证：`npm run build`；通过独立临时数据目录启动 Electron，交互检查布局、键盘、公式、搜索、工具转换及主题。不得注入假用户数据冒充功能。

## 4. 插件 SDK、打包与交付

文件：`examples/hello-nexlet/*`、`docs/plugin-sdk.md`、`README.md`、`tests/electron.spec.ts`。
提供可安装的示例插件与权限文档。使用独立测试目录验证真实宿主流程、持久化和权限拒绝。打包 Windows 应用并从打包产物验证启动；macOS 构建配置与实际执行范围分别记录。
验证：`npm test`、`npm run typecheck`、`npm run test:e2e`、`npm run package:win`。仅在新变更/失败时重复相关检查。

## 风险、写入与回滚

依赖安装访问 npm/Electron 下载服务并写入 `node_modules`；build 写 `dist`，package 写 `release`，测试写独立 `test-results`/临时用户目录。真实 UI 验证仅操作合成测试数据，不清理用户的 uTools 记录。平台回贴需实际接收方验证。
回滚：停止本次 Nexlet 进程，保留或移走 Nexlet 独立用户目录；本项目不修改系统全局配置、不执行 Git 操作。新工程文件均位于 `D:/code/Nexlet`，不会覆盖其他项目。
