# OCR 独立插件与宿主精简

用户已批准：OCR 改为完整离线插件，宿主不内置引擎、WASM、模型和识别界面；另外移除尚未使用的内置 FFmpeg。此前依赖、语言资源、Source map、差分打包优化保留。

## 行为与边界

- `plugins/ocr/` 独立构建 `nexlet-ocr.nexlet`，包含 PP-OCRv6 模型、校验清单、许可、WASM、识别 worker 和界面；不随宿主自动安装，不上传或发布。
- 普通插件安装后提供图片识别、图片识别复制、截图识别、截图识别复制四个命令；支持图片输入、文件选择/拖入/粘贴、结果编辑、复制、继续搜索、取消、超时和关闭清理。安装后可以离线识别。
- 宿主保留截图、贴图、图片输入及插件基础设施。移除内置 OCR 命令和专用识别进程，截图工具的 OCR 专用按钮移除；插件本身提供截图识别入口。
- 旧 OCR 命令的别名、快捷键、禁用状态和固定项映射到插件命令，保留已有新命令配置；未安装/禁用时命令不激活，卸载不清空这些偏好。
- 新增显式 `runtime.compute` 权限，仅允许已声明该权限的插件运行本地动态 JS、WASM 和本地 Worker。保留 sandbox/contextIsolation，无 Node、任意文件和直接外网访问。普通插件维持原 CSP。插件本地资源可使用同源 fetch，路径校验和大小上限统一执行。
- 插件包上限 64 MiB、解压总量 128 MiB、单文件 32 MiB，保留文件数、路径、软链接和重复条目检查；市场下载与本地安装使用同一限制。安装/更新仍由现有确认与权限流程控制。
- 增加通用 `search.returnToLauncher(text)` 和剪贴板快照/条件写入接口，用于保留继续搜索和识别复制期间不覆盖新剪贴板的行为；快照绑定插件会话、单次使用并在结束时清理。
- 移除 `ffmpeg-static` 依赖和打包规则；`media.ffmpeg` 保留显式 executable 调用，要求 media/files/process 权限；不再隐式提供或搜索 FFmpeg。

## 验收与回滚

宿主包不包含 OCR 模型、识别脚本、onnxruntime/PaddleOCR 或 ffmpeg-static；独立插件通过真实中英文截图识别、取消、权限隔离、停用/卸载测试。宿主原有截图、贴图、JSON、语言切换、启动与打包继续通过。

仅在当前 checkout 修改，不 commit、push、安装替换用户应用或发布。回滚按本任务文件差异恢复宿主 OCR 与依赖并卸载测试插件，保留用户数据库和原快捷键配置；旧命令映射保留旧键，允许旧版本继续读取。
