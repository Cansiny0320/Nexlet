# 固定签名发布与应用更新

用户已批准：macOS 和 Windows 安装版支持应用内检查、下载、重启安装；保留 Windows 便携版，便携版提供检查与下载。首次安装带更新器的版本仍需覆盖安装。

## 发布合同

- GitHub `Cansiny0320/Nexlet` 正式 Release 是更新来源，忽略草稿和预发布；不向客户端嵌入 GitHub 凭据。
- macOS Intel / Apple Silicon 均沿用 `69397314808BC8B95C8B4AF0FBDFA53C0184FC2C` 的固定证书，生成 DMG、ZIP、blockmap 和更新元数据。两架构元数据在发布前合并校验，不能互相覆盖。
- 加密 P12 与密码存为仓库 Actions Secrets，只在受信任分支/标签构建中导入临时钥匙串。PR 不读取凭据，继续 ad-hoc 构建验证。正式构建缺失凭据、指纹或签名不符必须失败。
- Windows 新增每用户 NSIS 安装包，保留现有便携 EXE 文件名。安装版支持自动替换，便携版展示正式 Release 的下载入口。
- 保留现有 Release 草稿策略，发布后才成为客户端可见更新。此次授权配置 Secrets；commit/push/tag/公开发布仍遵循用户 Git 边界。

## 客户端

复用 `electron-updater` 的稳定 v6 系列，独立主进程更新模块负责状态和受控操作，渲染层只能检查、下载、重启安装或打开固定仓库的版本下载页。设置页展示当前版本、新版本说明、下载进度、失败重试与安装操作。检查不直接下载，不自动重启；用户选择下载后提示下载完毕可重启安装，macOS 原生更新器可能在下次退出时应用已下载更新。

不降级、不跨架构、不安装预发布。开发模式不自动更新。请求超时、网络失败、元数据缺失、签名不匹配均显示可理解错误并保留当前应用。应用退出安装前允许已有稿纸保存和宿主清理完成。

## 压力测试结论

- 现有 DMG 不够，需提供 ZIP 和 latest-mac.yml；Windows portable 不属于 electron-updater 支持的更新格式，所以另加 NSIS。
- 固定证书已证明本机覆盖升级保留 TCC；Squirrel 仍需完成真实自动升级验证，不以 mock 或构建通过代替。
- 自签名不提供 Apple 公证，首次安装系统提示与自动更新验收分开记录。
- 验证失败不关闭签名校验或更换证书；回滚保留旧安装与数据，不改用户 TCC 记录。
