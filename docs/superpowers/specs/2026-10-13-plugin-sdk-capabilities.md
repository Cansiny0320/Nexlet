# Nexlet SDK 能力扩展

状态：用户已批准架构并要求实现、验证。2026-10-13。

## 目标与已批准边界

Nexlet SDK 的能力覆盖 uTools 的插件能力；不要求 uTools 的接口名称、同步调用语义、插件源码或安装包原样兼容。沿用 `window.nexlet`、Nexlet manifest、独立插件数据与权限声明。

前端保留 Electron sandbox、contextIsolation 与关闭 Node integration。能力通过类型明确的宿主 API 提供；Node.js 插件逻辑及重计算放独立进程。请求采用 Promise，事件采用可取消订阅，长任务可取消。已有 API 保持兼容。

账号、支付授权和云同步通过可配置服务接入。实现并验证服务适配能力，但不注册远程资源、不部署后端、不伪造用户或授权。未配置、不可用或平台不支持必须明确返回状态/错误；不能计作真实服务已接通。

| 系统 | 环境/版本/主题/常用路径，文件图标，文件打开/定位/回收站，本地文件读写/目录/元数据，进程运行与取消 |
| 屏幕与输入 | 显示器/坐标，屏幕和窗口截图，选区与取色，文本/文件/图片剪贴板，回贴、键鼠模拟及拖拽 |
| 数据 | 现有 KV 存储的删除/枚举，独立文档数据库与修订冲突、批量操作、查询与二进制附件 |
| 后台 | 独立 Node.js backend，RPC/事件/取消，持久定时任务及退出/停用/卸载后的资源清理 |

## 实现约束

- IPC 继续核验实际 webContents、主 frame、插件来源、安装记录及权限。拒绝未知方法和跨插件资源/任务句柄。
- 公共 API 合同独立于主程序 HostApi；类型不承诺未实现方法。以宿主合同为准同步插件仓类型，增加类型/运行时一致性验证。
- 文件读写、进程、本地 Node backend、浏览器自动化、屏幕采集和输入模拟使用明确权限。Node backend 具有本地 Node 权限；独立进程用于生命周期/崩溃隔离，不将它描述为 OS 沙箱。
- 插件自有 backend 必须从插件包内加载，禁止路径越界。停用/卸载/更新/退出关闭相应进程和任务；后台能力不依赖前端窗口常驻。
- 长任务使用归属明确的请求 ID、超时、取消和进度事件；关闭会话后不再投递旧结果。后台定时任务按插件身份归属，停用插件不触发。
- 子窗口和浏览器保持前端无 Node；远程浏览器页面不注入宿主插件 API。子窗口只拥有所属插件权限，插件之间不能操作对方窗口或会话。
- 数据与凭据按插件 ID 隔离，保留原 storage 行为，数据库增加独立存储命名空间/表。冲突不得静默覆盖；删除插件数据包括本次新增数据。
- 未配置外部 provider、缺少平台授权或可执行文件时明确报错。验证可使用临时 HTTP 服务、临时数据目录和无破坏性子进程；与真实服务联通验收分开报告。

## 验收

每一类能力需要可执行实现及相应验证，不能以方法存在或空实现代表完成。重点覆盖权限拒绝、跨插件隔离、异步任务取消、后台与窗口生命周期、数据库冲突、流式解析、provider 错误及旧插件回归。

本机验证与跨平台未运行项分别报告。macOS 的截图/输入模拟可能依赖系统授权；测试不得代替用户更改系统权限。测试不得改日常 Nexlet 数据或产生真实支付。
