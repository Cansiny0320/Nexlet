# 文件搜索提前准备与稳定状态展示

用户已批准：打开 Windows 文件搜索即准备索引；已有数据库复用；显示持续加载动画、等待时间和索引范围，不显示未经引擎提供的百分比；完成后自动搜索当前关键词。清空输入不停止后台准备，重开复用任务，失败明确显示重试。修复索引重试期间图标消失。

补充缺陷：安装版显示复制 Everything.exe 的 EBUSY。只读进程检查发现同一路径的引擎仍由 Nexlet 持有，之后版本探测恢复。当前 start 在探测失败后无条件复制可执行文件，因此连接短暂失败可能导致覆盖运行中的程序。

## 实现边界

- 独立 `fileSearchStatus` 接口负责启动和探测准备状态，不修改搜索结果授权或搜索请求代次；多个窗口共享正在进行的探测。
- UI 区分索引准备与搜索请求。轮询时保留状态图标和布局，结束后使用最新关键词，清空或离开忽略迟到响应。
- 索引显示准备中、就绪、不可用。超时只能说明暂未就绪，不据此声称扫描百分比；运行中的实例响应慢仍保持准备提示。
- 同一版本运行文件仅首次复制；拥有的存活进程直接复用。数据库和现有安装不删除、不重建。
- macOS 继续使用现有 Spotlight 行为。

## 压力测试结论

- 已核实空输入不启动引擎、每两秒重试的 busy 分支缺少图标、启动路径无条件 copyFile。
- 已核实官方 ES 文档未提供进度百分比；采用状态与耗时符合批准的交互。
- 重开、多窗口、范围变化、连接暂时失效、引擎退出、清空关键词均需覆盖。版本响应仅证明连接，不代表索引完成；须独立进行受限查询探测。
- 不需要新增领域术语或 ADR；不升级引擎、安装服务或更改索引范围。

## 验收

空白打开小范围测试目录即启动真实引擎；完成后可搜索测试文件；重复打开进程不变；准备状态跨轮询持续展示且计时递增；断开显示重试；清空不恢复旧结果；临时连接失败不复制或重启存活引擎。
