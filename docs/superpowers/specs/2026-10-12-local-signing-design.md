# 固定自签名证书与升级授权验证

用户已批准：先用长期保留的 Nexlet 自签名代码证书验证本机更新能否保留辅助功能授权；通过后再考虑发布流程。

## 范围

- 保持 `app.nexlet.desktop`，保留现有用户数据及已实现的主动授权提示。
- 在仓库外保存专用证书、加密私钥及独立钥匙串，不使用其他项目的签名身份，不上传凭据。
- 用同一证书构建两个不同版本并覆盖安装，比较签名身份和实际自动回贴行为。
- 提供本机重复打包入口与使用说明；本轮不改 GitHub Secrets、远端 workflow 或发布状态。

## 压力测试结论

- 自签名能提供稳定的代码身份，但不能据此宣称当前 macOS 一定保留辅助功能权限，必须实机验证。
- 丢失或重新创建私钥/证书会改变身份；签名入口须使用固定证书并在缺失时失败，不降级为 ad-hoc。
- 首次切换签名身份需要用户重新授权；后续测试不得重置权限或替用户批准权限后宣称自动保留。
- 不改变系统整体信任策略、Gatekeeper 或其他应用权限。若系统要求额外信任操作，明确说明具体范围后由用户处理。
- 自签名不等同于 Developer ID 公证，不作为公开分发的无提示安装承诺。

## 验收

两个不同版本的代码签名条件互相兼容；第一个版本获准后，覆盖第二个版本、重启并从测试文档唤起，自动回贴成功且未重新授权。若需要用户操作，只记录实际已验证的部分。

## 回滚

安装前备份 `/Applications/Nexlet.app`；可以恢复应用包，不覆盖用户数据库。证书留在专用目录供后续使用，不自动删除授权记录。
