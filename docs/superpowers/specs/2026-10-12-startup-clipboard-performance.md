# 启动与剪贴板性能优化（已批准）

## 目标与范围
用户于 2026-10-12 批准：工具按需加载、macOS 剪贴板变更检测，完成优化前后启动速度及内存对比。保持现有工具行为、未保存内容交接、Windows 剪贴板兼容性。不调整窗口回收、数据库分页、快捷键目标获取，不提交、推送或发布。

## 设计
- 首页同步加载 Launcher；其余内置工具页面通过模块顶层 React.lazy + dynamic import 按需加载，以 Suspense 展示加载状态、Error Boundary 展示失败。维持现有路由和页面状态语义，不后台预加载全部工具。
- 独立窗口恢复确认必须发生在实际工具挂载及恢复任务完成之后，移除现有固定 50 ms 的恢复确认。失败及超时不清理源工具；保留主进程 8 秒交接超时。
- macOS 复用 koffi 调用 AppKit/Objective-C 获取 NSPasteboard.generalPasteboard.changeCount。按现有 700 ms 周期检查，首次及变化时读取剪贴板；不变时不解码图片、不读取文本。
- 原生检测初始化/调用失败返回 null，沿用原有捕获路径；手动 force 捕获仍执行；采集成功才推进序号，采集期间的再次变化在下轮检查处理。保留隐私标记过滤、捕获互斥、尺寸限制和哈希去重。
- 原生库只在 macOS 首次需要检测时初始化，签名遵照 NSInteger / pointer 的平台 ABI，控制 Objective-C 临时对象生命周期。

## 基准与验收
- 冻结当前工作目录源码、依赖锁和构建配置为本地 before 快照；after 从相同快照仅应用本次优化文件，避免同期其他改动影响对比。独立产物、同一 Electron 和隔离数据目录，无 Git worktree。
- 使用相同生产前端构建，记录运行平台、版本、架构、哈希、样本及命令。应用通过 Electron 测试入口启动，不宣称等同已签名安装包。
- 新进程启动各 10 次（系统磁盘缓存不清空），测量启动至首页可交互，中位数及范围；记录工具首次与再次打开时间，前后交错顺序减少时间偏差。
- 固定窗口/数据/图像，采样首页静置、隐藏、大图剪贴板及 JSON 打开后的进程内存与 CPU。RSS 明确包含共享页重复计数，JS heap 仅辅助归因；不把单次波动当收益。
- 真实剪贴板测试短暂占用系统剪贴板，正常退出现有 Nexlet 避免写入正式历史，备份并恢复可恢复的格式，结束后重开。样本存放 .tmp，报告不包含用户剪贴板内容。
- 回归：lazy 首开/再开/失败/慢加载；JSON 与稿纸/文件搜索交接；原生序号稳定及变化、降级、force、失败重试、采集中变化、Windows 兼容。

## 风险及回滚
首次工具打开承担延迟加载成本；动态模块失败不得白屏或误确认交接。原生 ABI 错误可能崩溃，先在独立子进程验证；本机 arm64 可验，Intel 运行态明确不宣称通过。回滚仅还原本次变更，利用 before 快照核对，不覆盖同期改动。
