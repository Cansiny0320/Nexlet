# Nexlet UI 对齐

## 已批准范围

用户要求修复插件市场布局及新版界面中未统一样式的控件；设备登录页先用 ImageGen 形成参考图，已批准按图实施。2026-10-26 用户取消 Figma 前置步骤，明确要求直接照 UI 图还原，并逐页截图检查是否还原。其他现有页面暂不扩大代码改动范围。

- 登录参考：`docs/design/ui-alignment-2026-10-26/device-login-reference.png`。
- 桌面参考：`docs/design/ui-alignment-2026-10-26/desktop-ui-reference.png`。
- Figma 初稿仅作为已有记录，不再作为实施依赖或最终验收依据。

## 目标与约束

1. 插件市场按可用宽度排列紧凑卡片，版本与操作分组明确；搜索、筛选、详情与任务操作沿用现有功能。
2. AI、OCR/翻译、账号同步、配置导入导出使用项目已有的表单组件与统一折叠区样式，处理窄窗口、深色主题、键盘焦点及错误状态。
3. PDF 工具、图片批处理和批量重命名使用参考图的双栏工具布局、文件列表和明确的操作区；保留现有字段、选项、状态、DOM ID 和处理逻辑。
4. 截图编辑器使用可识别的图标工具栏，保留工具、标注、长截图、OCR、复制和保存等功能及可访问名称。
5. 设备登录页还原居中面板、品牌、账号行、代码输入与操作布局。保留三种语言、GitHub 登录、设备校验和人工确认。加载、失败、确认及拒绝状态在同一布局中呈现。

不新增设置侧栏、PDF 翻页等参考图中未经产品实现支持的功能；不使用生成图中的虚构插件资料。桌面沿用项目字体及主题变量；Figma 若缺少系统字体，明确记录替代字体。其他页面只创建设计稿，保留现有信息架构。

## 根因及方案

- 插件市场固定两列使宽窗口卡片过宽，底部新增详情按钮后仍用三项 `space-between`，描述和平台信息的固定留白放大问题。改成自适应网格、独立操作组、次要元信息在详情中展示。
- 能力配置的 `details/summary/textarea` 缺少统一样式。复用 `Input`、`Textarea`、`Button`、`SettingsSelect`、`Switch`，对折叠区提供一致的间距与焦点反馈。
- 三个文件工具的共享 CSS 只覆盖基础控件，无法表达文件、参数、结果之间的层次。完善共享布局和表单样式，避免改动处理协议。
- 登录页仅有浏览器原生元素及基础尺寸，缺少布局和状态层次。使用本地样式与已有品牌 SVG；不依赖外部字体、脚本或服务。

## 设计复核

- 图片与 Figma 都是设计依据，完整 UI 图片不能充当可编辑设计稿或实现背景。
- 卡片描述不因固定高度被截断；窄窗口工具栏换行，列表和表单不溢出。
- 错误及不可用原因仍可见；保留权限确认与破坏性操作原有确认流程。
- 登录代码与账号采用演示值进行视觉测试，测试不得请求实际授权端点。
- 验证通过后不自动 commit、push、发布或部署；本轮未授权这些动作。

## 验收

- 使用真实 HTML、控件和图标还原界面，不用整图替代可交互界面。
- 实现与对应设计对照，宽窄窗口、浅深主题可用，无文本遮挡、横向溢出、错位按钮。
- 筛选、详情、配置保存、登录状态与文件工具关键交互保持原有语义。
- 静态检查、构建和相关非侵入测试通过；记录不相关的基线失败。
